# ACP2E-4799: GraphQL-Abfrage `requisition_lists` gibt falsche `total_count` mit Paginierung zurück

Mit dem Patch ACP2E-4799 wird das Problem behoben, bei dem die `requisition_lists` GraphQL-Abfrage einen falschen `total_count` zurückgibt, der nur die Anzahl der Elemente auf der aktuellen Seite anstelle der Gesamtzahl der Anforderungslistenentitäten widerspiegelt, die den Abfragekriterien entsprechen. Dieser Patch ist verfügbar, wenn [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.82 installiert ist. Die Patch-ID lautet ACP2E-4799. Dieses Problem wird voraussichtlich in Adobe Commerce B2B 1.5.4 behoben.

## Betroffene Produkte und Versionen

**Der Patch wird für die Adobe Commerce-Version erstellt:**

* Adobe Commerce (alle Bereitstellungsmethoden) B2B 1.5.2-p4

**Kompatibel mit Adobe Commerce-Versionen:**

* Adobe Commerce (alle Bereitstellungsmethoden) B2B >=1.5.0 &lt;1.5.3

>[!NOTE]
>
>Der Patch könnte mit neuen [!DNL Quality Patches Tool]-Versionen auch für andere Versionen gelten. Um zu überprüfen, ob der Patch mit Ihrer Adobe Commerce-Version kompatibel ist, aktualisieren Sie das `magento/quality-patches` auf die neueste Version und überprüfen Sie die Kompatibilität auf der Seite [[!DNL Quality Patches Tool]: Nach Patches suchen](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Verwenden Sie die Patch-ID als Suchbegriff, um den Patch zu finden.

## Problem

Wenn Kunden Anforderungslisten mit Paginierung abfragen, spiegelt das `total_count` nicht die vollständige Anzahl der passenden Anforderungslisten wider. Stattdessen wird nur die Anzahl der für die aktuelle Seite zurückgegebenen Elemente angezeigt, wodurch die Paginierungsmetadaten ungenau sind.

<u>Voraussetzungen</u>:

Anforderungslisten sind für Adobe Commerce B2B aktiviert.

<u>Schritte zur Reproduktion</u>:

1. Gehen Sie in der Admin zu **[!UICONTROL Stores]** > **Einstellungen** > **Konfiguration**.
1. Wählen Sie im linken Bedienfeld unter **Allgemein** die Option **B2B-Funktionen**.
1. Legen Sie **[!UICONTROL Enable Requisition List]** auf **[!UICONTROL Yes]** fest und wählen Sie **[!UICONTROL Save Config]** aus.
1. Melden Sie sich bei der Storefront als Kunde an.
1. Wählen Sie &quot;**[!UICONTROL My Requisition Lists]**&quot; und erstellen Sie sechs Anforderungslisten.
1. Stellen Sie sicher, dass der Kunde über genau sechs Anforderungslisten verfügt und dass jeder Listenname `ABC` enthält, sodass alle sechs Listen mit der gefilterten Abfrage übereinstimmen.
1. Führen Sie die folgende GraphQL-Abfrage aus, wobei `pageSize` auf zwei und `currentPage` auf eins gesetzt ist:

   ```graphql
   query {
     customer {
       requisition_lists(
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```

1. Führen Sie diese GraphQL-Abfrage aus:

   ```graphql
   query {
     customer {
       requisition_lists(
         filter: { name: { match: "%ABC%" } }
         pageSize: 2
         currentPage: 1
       ) {
         items {
           uid
           name
         }
         total_count
         page_info {
           current_page
           page_size
           total_pages
         }
       }
     }
   }
   ```


<u>Erwartete Ergebnisse</u>:

* Die `requisition_lists` Abfrage gibt `total_count` zurück, die der Gesamtzahl der Anforderungslisten des Kunden entspricht, unabhängig von `pageSize` und `currentPage`.
* Die Paginierungsdaten bleiben konsistent mit dem vollständigen übereinstimmenden Ergebnissatz.

<u>Tatsächliche Ergebnisse</u>:

`total_count` Gibt nur die Anzahl der Elemente auf der aktuellen Seite zurück, z. B. zwei statt sechs.

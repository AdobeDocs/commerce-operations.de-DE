# ACP2E-5122: Verarbeitete GraphQL-Warenkorbfehler werden fälschlicherweise in das Ausnahmeprotokoll geschrieben

Mit dem Patch ACP2E-5122 wird das Problem behoben, dass behandelte GraphQL-Warenkorbanfragefehler als Anwendungsfehler in das Ausnahmelogo geschrieben werden. Dieser Patch ist verfügbar, wenn [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84 installiert ist. Die Patch-ID lautet ACP2E-5122. Dieses Problem wird voraussichtlich in Adobe Commerce 2.4.10 behoben.

## Betroffene Produkte und Versionen

**Der Patch wird für die Adobe Commerce-Version erstellt:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.8-p5

**Kompatibel mit Adobe Commerce-Versionen:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.4 - 2.4.9

>[!NOTE]
>
>Der Patch könnte mit neuen [!DNL Quality Patches Tool]-Versionen auch für andere Versionen gelten. Um zu überprüfen, ob der Patch mit Ihrer Adobe Commerce-Version kompatibel ist, aktualisieren Sie das `magento/quality-patches` auf die neueste Version und überprüfen Sie die Kompatibilität auf der Seite [[!DNL Quality Patches Tool]: Nach Patches suchen](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Verwenden Sie die Patch-ID als Suchbegriff, um den Patch zu finden.

## Problem

Behandelte GraphQL-Warenkorbanfragefehler werden als Anwendungsfehler in das Ausnahmelog geschrieben.

<u>Schritte zur Reproduktion</u>:

1. Senden Sie eine GraphQL `placeOrder`-Mutation mit einer ungültigen, abgelaufenen oder bereits zerstörten maskierten Warenkorb-ID wie diese Mutation:

   ```
       mutation {
           placeOrder(input: { cart_id: "test" }) {
               orderV2 {
                   id
                   number
               }
           }
       }
   ```

1. Überprüfen Sie die GraphQL-Antwort.
1. Überprüfen Sie `var/log/exception.log` auf den Fehler beim Warenkorb.

<u>Erwartete Ergebnisse</u>:

1. Die GraphQL-Anfrage gibt eine verarbeitete Client-seitige Fehler-Payload für den ungültigen Warenkorb ohne eine *HTTP 500*-Antwort zurück.
1. Die behandelte *GraphQlNoSuchEntityException* wird nicht in `var/log/exception.log` geschrieben und stattdessen in einen Protokollkanal mit niedrigerem Schweregrad weitergeleitet.

<u>Tatsächliche Ergebnisse</u>:

Jede Anfrage schreibt die behandelte Ausnahme in `var/log/exception.log` mit `report.ERROR` Schweregrad, was bei wiederholten Anfragen zu unbegrenztem Protokollwachstum führt.

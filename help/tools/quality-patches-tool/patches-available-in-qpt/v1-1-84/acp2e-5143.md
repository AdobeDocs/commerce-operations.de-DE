# ACP2E-5143: GraphQL `route`-Abfrage rendert nicht angeforderten CMS-Seiteninhalt

Der Patch ACP2E-5143 behebt das Problem, dass die GraphQL `route`-Abfrage den gesamten CMS-Seiteninhalt einschließlich Page Builder-Widgets und Produktlisten rendert, selbst wenn nur URL-Routing-Felder angefordert werden, was die URL-Auflösung verlangsamt. Dieser Patch ist verfügbar, wenn [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84 installiert ist. Die Patch-ID lautet ACP2E-5143. Dieses Problem wird voraussichtlich in Adobe Commerce 2.4.10 behoben.

## Betroffene Produkte und Versionen

**Der Patch wird für die Adobe Commerce-Version erstellt:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.7-p9

**Kompatibel mit Adobe Commerce-Versionen:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.4 - 2.4.7-p10

>[!NOTE]
>
>Der Patch könnte mit neuen [!DNL Quality Patches Tool]-Versionen auch für andere Versionen gelten. Um zu überprüfen, ob der Patch mit Ihrer Adobe Commerce-Version kompatibel ist, aktualisieren Sie das `magento/quality-patches` auf die neueste Version und überprüfen Sie die Kompatibilität auf der Seite [[!DNL Quality Patches Tool]: Nach Patches suchen](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Verwenden Sie die Patch-ID als Suchbegriff, um den Patch zu finden.

## Problem

Problem, bei dem die GraphQL `route`-Abfrage den gesamten CMS-Seiteninhalt einschließlich Page Builder-Widgets und Produktlisten rendert, selbst wenn nur URL-Routing-Felder angefordert werden, was die URL-Auflösung verlangsamt.

<u>Voraussetzungen</u>:

Page Builder ist installiert.

<u>Schritte zur Reproduktion</u>:

1. Gehen Sie zu Admin > **[!UICONTROL Content]** > **[!UICONTROL Elements]** > **[!UICONTROL Pages]** und klicken Sie auf **[!UICONTROL Add New Page]**.
1. Geben Sie die Seitendetails ein, legen Sie **[!UICONTROL Enable Page]** auf **[!UICONTROL Yes]** fest und klicken Sie im Abschnitt **[!UICONTROL Content]** auf **[!UICONTROL Edit with Page Builder]** . Erweitern Sie **[!UICONTROL Add Content]** im Bedienfeld „Seiten-Builder“ und ziehen Sie einen **[!UICONTROL Products]** Platzhalter auf die Bühne oder fügen Sie ein Katalog-Produkt-Widget in den Seiteninhalt ein.
1. Gehen Sie in Admin zu **[!UICONTROL Stores]** > **[!UICONTROL Settings]** > **[!UICONTROL Configuration]**. Wählen Sie im linken Bedienfeld unter **[!UICONTROL General]** die Option **[!UICONTROL Web]** und erweitern Sie dann **[!UICONTROL Default Pages]**. Legen Sie **[!UICONTROL CMS Home Page]** auf die neue Seite fest und klicken Sie auf **[!UICONTROL Save Config]**.
1. Senden Sie die folgende GraphQL-Anfrage:

   ```
   query ResolveURL($url: String!) {
     route(url: $url) {
       relative_url
       redirect_code
       type
       ... on CmsPage { identifier __typename }
       ... on ProductInterface { uid __typename }
       ... on CategoryInterface { uid __typename }
       __typename
     }
   }
   ```

1. Verwenden Sie die folgenden Variablen für die Anfrage:

   ```
   { "url": "/" }
   ```

<u>Erwartete Ergebnisse</u>:

Die `route` Abfrage gibt die angeforderten Routing-Metadaten und Typdiskriminatorfelder für die CMS-Homepage zurück, ohne den vollständigen Inhalt zu rendern.

<u>Tatsächliche Ergebnisse</u>:

1. Die `route` Abfrage rendert den vollständigen Inhalt der CMS-Startseite, obwohl nur Routing-Metadaten und Typdiskriminatorfelder angefordert werden.
1. Page Builder-Widgets laden Produktsammlungen, wodurch die Antwortzeit und die Anzahl der Datenbankabfragen pro Anfrage erhöht werden.

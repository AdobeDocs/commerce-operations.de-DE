# ACP2E-4913: REST-API-Versand und Rechnungserstellung werden nach einem Datenbank-Deadlock nicht erneut versucht

Mit dem Patch ACP2E-4913 wird das Problem behoben, dass das Erstellen einer Sendung oder einer Rechnung über die REST-API dauerhaft fehlschlägt, wenn ein Datenbank-Deadlock auftritt, da der Vorgang nicht erneut versucht wird. Dieser Patch ist verfügbar, wenn [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.84 installiert ist. Die Patch-ID lautet ACP2E-4913. Dieses Problem wird voraussichtlich in Adobe Commerce 2.4.10 behoben.

## Betroffene Produkte und Versionen

**Der Patch wird für die Adobe Commerce-Version erstellt:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.8-p3

**Kompatibel mit Adobe Commerce-Versionen:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.7 - 2.4.8-p5

>[!NOTE]
>
>Der Patch könnte mit neuen [!DNL Quality Patches Tool]-Versionen auch für andere Versionen gelten. Um zu überprüfen, ob der Patch mit Ihrer Adobe Commerce-Version kompatibel ist, aktualisieren Sie das `magento/quality-patches` auf die neueste Version und überprüfen Sie die Kompatibilität auf der Seite [[!DNL Quality Patches Tool]: Nach Patches suchen](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Verwenden Sie die Patch-ID als Suchbegriff, um den Patch zu finden.

## Problem

Das Erstellen einer Sendung oder Rechnung über die REST-API schlägt dauerhaft fehl, wenn ein Datenbank-Deadlock auftritt, da der Vorgang nicht erneut versucht wird.

<u>Schritte zur Reproduktion</u>:

1. Bereiten Sie mehrere Aufträge vor, die versendet werden können, und mehrere Aufträge, die fakturiert werden können.
1. Senden Sie für diese Bestellungen mehrere `POST /rest/V1/order/<orderId>/ship` parallel, da eine Integration möglicherweise nicht geladen wird.
1. Gleichzeitiges Senden mehrerer `POST /rest/V1/order/<orderId>/invoice`-Anfragen
1. Überprüfen Sie die API-Antworten und -`var/log/exception.log`.

<u>Erwartete Ergebnisse</u>:

Nach einem Deadlock wird der Vorgang wiederholt, und die Lieferung oder Rechnung wird erstellt.

<u>Tatsächliche Ergebnisse</u>:

Einige Anfragen schlagen mit dem folgenden Deadlockfehler fehl. Die Lieferung oder Rechnung wird nicht erstellt und muss manuell erstellt werden:

```
SQLSTATE[40001]: Serialization failure: 1213 Deadlock found when trying to get lock; try restarting transaction
```

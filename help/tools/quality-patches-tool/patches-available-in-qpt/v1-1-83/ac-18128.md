# AC-18128: GraphQL-Bestelldaten und Kommentar-Zeitstempel sind für nicht englische Gebietsschemata falsch

Der AC-18128 Patch behebt das Problem, dass von GraphQL zurückgegebene Bestelldaten und Bestellkommentar-Zeitstempel falsche Kalenderdaten in nicht englischen Gebietsschemaeinstellungen anzeigen können. Dieser Patch ist verfügbar, wenn [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 installiert ist. Die Patch-ID ist AC-18128. Beachten Sie, dass dieses Problem in Adobe Commerce 2.4.8 behoben wurde.

## Betroffene Produkte und Versionen

**Der Patch wird für die Adobe Commerce-Version erstellt:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.8

**Kompatibel mit Adobe Commerce-Versionen:**

* Adobe Commerce (alle Bereitstellungsmethoden) >=2.4.8 &lt;2.4.8-p6

>[!NOTE]
>
>Der Patch könnte mit neuen [!DNL Quality Patches Tool]-Versionen auch für andere Versionen gelten. Um zu überprüfen, ob der Patch mit Ihrer Adobe Commerce-Version kompatibel ist, aktualisieren Sie das `magento/quality-patches` auf die neueste Version und überprüfen Sie die Kompatibilität auf der Seite [[!DNL Quality Patches Tool]: Nach Patches suchen](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html). Verwenden Sie die Patch-ID als Suchbegriff, um den Patch zu finden.

## Problem

Von GraphQL zurückgegebene Zeitstempel für Bestelldaten und Bestellkommentare können in anderen Gebietsschemaeinstellungen falsche Kalenderdaten anzeigen.

<u>Schritte zur Reproduktion</u>:

1. Navigieren Sie im Admin-Bedienfeld zu **[!UICONTROL Stores]** > **[!UICONTROL Configuration]** > **[!UICONTROL General]** > **[!UICONTROL Locale Options]**. Setzen Sie **[!UICONTROL Timezone]** auf *Europe/Paris*. Setzen Sie **[!UICONTROL Locale]** auf *Französisch (Frankreich)*. Speichern Sie die Konfiguration.
1. Bestellen Sie in der Storefront.
1. Führen Sie die folgende GraphQL-Abfrage für Kundenaufträge aus:

   ```graphql
   query getOrders {
       customer {
           orders {
               items {
                   orderDateOK: created_at
                   orderDateFAIL: order_date
               }
           }
       }
   }
   ```

<u>Erwartete Ergebnisse</u>:

Die Zeitstempel für Bestelldatum und Kommentar in GraphQL-Antworten spiegeln das richtige Kalenderdatum wider, unabhängig vom Gebietsschema des Stores.

<u>Tatsächliche Ergebnisse</u>:

Bei nicht `en_US` Gebietsschemata wie `fr_FR` und `de_DE` zeigt `order_date` aufgrund eines Problems bei der Datumsanalyse das falsche Kalenderdatum an.

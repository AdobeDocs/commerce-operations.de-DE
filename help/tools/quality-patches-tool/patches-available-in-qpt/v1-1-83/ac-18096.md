# AC-18096: Datumsfelder für Sales GraphQL geben ein falsches lokalisiertes Format zurück

Der AC-18096-Patch behebt das Problem, dass Datumsfelder von Sales GraphQL Datumsangaben in einem anderen Format als frühere Versionen zurückgeben, indem das Datumsformat von Schrägstrichen getrennten `/` auf Bindestriche getrennte `-` zurückgesetzt wird. Dieser Patch ist verfügbar, wenn [[!DNL Quality Patches Tool (QPT)]](/help/tools/quality-patches-tool/quality-patches-tool-to-self-serve-quality-patches.md) 1.1.83 installiert ist. Die Patch-ID ist AC-18096. Beachten Sie, dass dieses Problem in Adobe Commerce 2.4.9 behoben wurde.

## Betroffene Produkte und Versionen

**Der Patch wird für die Adobe Commerce-Version erstellt:**

* Adobe Commerce (alle Bereitstellungsmethoden) 2.4.9

**Kompatibel mit Adobe Commerce-Versionen:**

* Adobe Commerce (alle Bereitstellungsmethoden) >2.4.8 &lt;=2.4.9-p1

>[!NOTE]
>
>Der Patch könnte mit neuen [!DNL Quality Patches Tool]-Versionen auch für andere Versionen gelten. Um zu überprüfen, ob der Patch mit Ihrer Adobe Commerce-Version kompatibel ist, aktualisieren Sie das `magento/quality-patches` auf die neueste Version und überprüfen Sie die Kompatibilität auf der Seite [[!DNL Quality Patches Tool]: Nach Patches suchen](https://experienceleague.adobe.com/tools/commerce-quality-patches/index.html?lang=de). Verwenden Sie die Patch-ID als Suchbegriff, um den Patch zu finden.

## Problem

Die Datumsfelder von Sales GraphQL geben Datums- und Zeitwerte im Schrägstrichformat `(d/m/Y H:i:s)` anstelle des in Adobe Commerce 2.4.8 verwendeten strichgetrennten Formats `(Y-m-d H:i:s)`

<u>Voraussetzungen</u>:

- **[!UICONTROL General]** > **[!UICONTROL Locale Options]** > **[!UICONTROL Timezone]**: *Europe/Paris*
- **[!UICONTROL General]** > **[!UICONTROL Locale Options]** > **[!UICONTROL Locale]**: *Französisch (Frankreich)*

<u>Schritte zur Reproduktion</u>:

1. Erstellen Sie eine Bestellung.
1. Abrufen von Details zum Bestelldatum mit GraphQL:

   ```graphql
   query getOrders {
       customer {
           orders {
               items {
                   orderDateOK: created_at
                   orderDateFAIL: order_date
               }
           }
       }
   }
   ```

<u>Erwartete Ergebnisse</u>:

- Die Felder geben Werte in `Y-m-d H:i:s` zurück, die mit der Ausgabe in Version 2.4.8 übereinstimmen.

<u>Tatsächliche Ergebnisse</u>:

- Die Felder geben Werte in `d/m/Y H:i:s` zurück, z. B. `27/08/2026 14:12:55`, anstelle von `Y-m-d H:i:s`, z. B. `2026-08-27 14:12:55`.
